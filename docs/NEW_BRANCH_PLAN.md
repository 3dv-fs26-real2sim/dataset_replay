# Minimal Single-Arm + OAK-D Branch — Implementation Plan

> **Status:** investigation complete · awaiting implementation
> **Scope:** new git branch in `dataset_replay/` for a single right-arm Panda + OrcaHand on a procedural table+walls scene with OAK-D Pro AF camera and AprilTag extrinsic calibration.
> **Generated by:** investigation across `dataset_replay/`, `pandaorca_description/`, `USDs/orcav1b_franka_vmnt_v10_flattened.usda`, and the Isaac Sim install in conda env `3dv`.

## 1. Executive Summary

### What changes vs. the current `main`

| Concern | Current `main` | New minimal branch |
|---|---|---|
| Robot rig | Bimanual: panda + OrcaHand on **left** and **right** | **Right arm only** |
| Robot asset | `dataset_replay/assets/orcav1b_franka_vmnt_v10_flattened.usd` (per memory; confirmed already pointed there in `constants.py`) | Same file at **`/home/shinben0327/3dv/USDs/orcav1b_franka_vmnt_v10_flattened.usd`** (single source of truth — copy in or reference in place) |
| Scene construction | Hand-rolled `UsdGeom.Mesh` ground + table (single fixed cuboid) | Procedural **table + 3 walls (U-shape)** with **wood texture**, **AprilTag plane**, all parameter-driven via a Python dataclass |
| Camera | Aria (head-mounted, per-arm extrinsics, hard-coded intrinsics) | **OAK-D Pro AF only**, **fixed in the world frame**, extrinsic calibrated via **AprilTag** |
| Camera extrinsic source | Hardcoded in `constants.ARIA_EXTRINSICS` + optional `--refined-extrinsic` `.npz` override | Output of a new `calibrate_extrinsic.py` written to `assets/calibration/oakd_extrinsic.npz` |
| Object pose trajectories | `poses_<obj>_{vda,depthpro,dav3_tablescale}.npz`, multiple variants per object, all in Aria-camera frame | **One** trajectory file per (task, object), in **world frame** (or with explicit camera-frame metadata) |
| H5 ingestion | Dual-mode fallback ladder, Aria image keys default | New **`H5Reader` adapter** with explicit single-arm contract; concrete reader stubbed until sample file is supplied |
| Scripts | `kinematic_replay`, `dynamic_replay`, `test_setup`, `record_h5`, `calculate_table_depth`, `render_table_depth` | **Drop** `dynamic_replay`, `calculate_table_depth`, `render_table_depth`. **Keep** simplified versions of `kinematic_replay`, `test_setup`, `record_h5`. **Add** `calibrate_extrinsic`. |
| `pandaorca_description/` | Referenced only in docs; URDF was already cloned into `dataset_replay/assets/urdf/` | **Drop the dependency entirely.** Branch is self-contained against the `/USDs/` USD + the in-repo URDF/Lula descriptor. |

### Top-level deliverables of the new branch

1. **`config.py`** — single `SceneConfig` dataclass (table size, wall heights, mount pose, camera intrinsics, AprilTag spec, paths). Pure-Python config per the agreed simplification scope.
2. **`scene.py`** — procedural builder: ground, table, three walls, AprilTag plane, lighting; references the orcav1b USD as the right-arm articulation.
3. **`textures.py`** — net-new MDL/UsdPreviewSurface helper to apply image textures to mesh prims (no precedent in the existing repo — must be written from scratch).
4. **`camera.py`** — rewritten to spawn one OAK-D camera with fixed `T_world_cam` from a calibration file.
5. **`calibrate_extrinsic.py`** — offline script: take an OAK-D image (from H5 or a single capture), detect AprilTag, solve PnP given the known on-table tag pose, write `oakd_extrinsic.npz`.
6. **`h5_loader.py`** — `H5Reader` adapter class with the contract documented in §6.7. Concrete reader is a TODO until you supply the sample file.
7. **`kinematic_replay.py`** — entry script collapsed to single-arm, single-camera, single-trajectory replay.
8. **Reorganized `data/` and `objects/` layouts** as proposed in §4.

**Implication:** all new code must use the `isaacsim.*` namespace + raw `pxr.*`. **The non-negotiable bootstrapping rule** (already followed by the existing repo): construct `SimulationApp` first, **then** import everything from `pxr.*`, `omni.*`, `isaacsim.*`. Honour this in every entry script.

## 6. Module Design Specs

### 6.1 `utils/config.py` — `SceneConfig` dataclass (NEW)

Pure-Python config (no YAML, per agreed scope). Single source of truth for all scene parameters; entry scripts may override fields programmatically.

```python
# scripts/utils/config.py
from __future__ import annotations
from dataclasses import dataclass, field
from pathlib import Path
import numpy as np

PROJECT_ROOT = Path(__file__).resolve().parents[2]
ASSETS = PROJECT_ROOT / "assets"

@dataclass
class TableConfig:
    size_xyz: tuple[float, float, float] = (1.0, 1.4, 0.05)  # Lx, Ly, top thickness
    top_z: float = 0.75                                       # world Z of the top surface
    centre_xy: tuple[float, float] = (0.0, 0.0)              # world XY of table centre
    texture_path: Path = ASSETS / "textures" / "wood.jpg"

@dataclass
class WallsConfig:
    # U-shape opening toward +X (the side the arm faces).
    # "Back" wall sits at the −X edge of the table, "left" at +Y, "right" at −Y.
    back_height:  float = 0.30
    left_height:  float = 0.20
    right_height: float = 0.20
    thickness:    float = 0.02
    texture_path: Path = ASSETS / "textures" / "wood.jpg"

@dataclass
class AprilTagConfig:
    family:    str = "tag36h11"
    tag_id:    int = 0
    edge_size: float = 0.10                          # m (black square edge)
    image_path: Path = ASSETS / "textures" / "apriltag_0.png"
    # Position relative to the table-top centre, on +Z by 1 mm to avoid z-fighting:
    pose_on_table: np.ndarray = field(
        default_factory=lambda: np.array([
            [1, 0, 0,  0.20],
            [0, 1, 0,  0.00],
            [0, 0, 1,  0.001],
            [0, 0, 0,  1.0],
        ], dtype=float))

@dataclass
class RobotMountConfig:
    # World pose of where the wrapper Xform that references the USD lives.
    # Note: panda_link0 has a non-trivial local translate inside the USD
    # (-0.00761, -0.00027, -0.47602). The wrapper transform must compensate
    # so panda_link0's *origin* sits at `mount_xyz`.
    mount_xyz: tuple[float, float, float] = (0.40, 0.0, 0.75)   # on table-top, near front edge
    mount_rpy: tuple[float, float, float] = (0.0, 0.0, 0.0)     # facing +X by default
    panda_link0_local_translate: tuple[float, float, float] = (
        -0.00761, -0.00027, -0.47602)                            # constant from the USD

@dataclass
class CameraConfig:
    name: str = "oakd_front_view"
    width:  int = 1280
    height: int = 720
    intrinsics: dict = field(default_factory=lambda: {
        "fx": 0.0, "fy": 0.0, "cx": 0.0, "cy": 0.0,             # Q6 — must be filled
    })
    extrinsic_path: Path = ASSETS / "calibration" / "oakd_extrinsic.npz"
    # Fallback nominal pose used if extrinsic_path is absent (e.g. for a fresh
    # calibration session). Replay refuses to start with the nominal pose.
    nominal_T_world_cam: np.ndarray | None = None

@dataclass
class SceneConfig:
    table:    TableConfig    = field(default_factory=TableConfig)
    walls:    WallsConfig    = field(default_factory=WallsConfig)
    apriltag: AprilTagConfig = field(default_factory=AprilTagConfig)
    robot:    RobotMountConfig = field(default_factory=RobotMountConfig)
    camera:   CameraConfig   = field(default_factory=CameraConfig)
    robot_asset_path: Path   = ASSETS / "orcav1b_franka_vmnt_v10_flattened.usd"
    urdf_path:        Path   = ASSETS / "urdf" / "panda_arm.urdf"
    lula_descriptor:  Path   = ASSETS / "lula" / "panda_arm_descriptor.yaml"
```

**Why a dataclass and not YAML:** simpler to keep a single source of truth in code, fewer moving parts, easy programmatic overrides for experiments. Per the agreed scope.

### 6.2 `utils/constants.py` — slim version (REWRITE)

Mostly removes constants and keeps just the few that are intrinsic to the robot kinematic chain (joint names, home pose, URDF EE-wrist offsets) — values that don't belong in `SceneConfig` because they're wired into the robot model, not a scene knob.

Keep:
- `ARM_JOINT_NAMES = ["panda_joint1", ..., "panda_joint7"]`
- `HAND_JOINT_NAMES` (the 17 `right_*` joint names from the USD — reuse the existing list, but only the right-side variant)
- `WRIST_HOME_POSITION`, `WRIST_HOME_ROTATION` (the home wrist target)
- `HOME_ARM_JOINTS_GUESS` (warm-start for IK)
- `HAND_HOME_JOINT_VALUES` (17 values, reuse existing values that map onto OrcaHand resting pose)
- `EE_WRIST_OFFSET_IN_LINK8` (the offset from `panda_link8` flange to the OrcaHand wrist frame — required for IK; this should be kept as-is since the hand-mount geometry is unchanged)
- `Q_TOOL_TO_URDF` (rotation between tool-frame quaternion convention and URDF link8 frame — used by `rotation.tool_quat_to_urdf`)

Drop:
- `FRANKA_LEFT_PATH`, `FRANKA_RIGHT_PATH` → replaced by a single `ROBOT_PRIM_PATH = "/World/Robot"`.
- `ARIA_INTRINSICS`, `ARIA_EXTRINSICS`, `CAMERA_CONFIGS` → moved into `SceneConfig.camera`.
- `OBJECT_POSE_PATHS`, `OBJECT_POSE_VERSIONS` → no per-version variants.
- `TABLE_PRIM_PATH`, `PANDA_LINK0_INTERNAL_OFFSET`, `ROBOT_BASE_WORLD_POSITIONS` → moved into `SceneConfig`.

### 6.4 `utils/textures.py` — texture binding helper (NEW — net-new code)

The existing repo has **zero** `UsdShade` / MDL usage. This module is fresh. Use `UsdPreviewSurface` (cross-renderer, file-texture-based) — no MDL dependency:

```python
# scripts/utils/textures.py
from pathlib import Path
from pxr import Sdf, Usd, UsdGeom, UsdShade

def bind_texture(stage: Usd.Stage, mesh_prim_path: str,
                 texture_path: Path, *, material_name: str | None = None,
                 uv_repeat: tuple[float, float] = (1.0, 1.0)) -> None:
    """Apply a `UsdPreviewSurface` material with a file-backed diffuse texture
    to the mesh at `mesh_prim_path`. Idempotent: re-uses an existing material
    of the same name if present.
    """
    mesh_prim = stage.GetPrimAtPath(mesh_prim_path)
    assert mesh_prim, f"missing prim: {mesh_prim_path}"

    mat_name = material_name or f"{Path(texture_path).stem}_mat"
    mat_path = Sdf.Path(f"/World/Looks/{mat_name}")
    material = UsdShade.Material.Define(stage, mat_path)

    shader = UsdShade.Shader.Define(stage, mat_path.AppendChild("surface"))
    shader.CreateIdAttr("UsdPreviewSurface")
    shader.CreateInput("useSpecularWorkflow", Sdf.ValueTypeNames.Int).Set(0)

    tex = UsdShade.Shader.Define(stage, mat_path.AppendChild("diffuseTex"))
    tex.CreateIdAttr("UsdUVTexture")
    tex.CreateInput("file", Sdf.ValueTypeNames.Asset).Set(str(texture_path))
    tex.CreateInput("st", Sdf.ValueTypeNames.Float2).ConnectToSource(
        UsdShade.Shader.Define(stage, mat_path.AppendChild("uvReader")).CreateIdAttr("UsdPrimvarReader_float2") or None
    )
    # (UV reader → uvReader.varname=st; tile via "scale" input on uvReader if needed.)
    shader.CreateInput("diffuseColor", Sdf.ValueTypeNames.Color3f).ConnectToSource(
        tex.CreateOutput("rgb", Sdf.ValueTypeNames.Float3))

    material.CreateSurfaceOutput().ConnectToSource(
        shader.CreateOutput("surface", Sdf.ValueTypeNames.Token))

    UsdShade.MaterialBindingAPI(mesh_prim).Bind(material)

    # Ensure the mesh has UVs. For a procedurally-built UsdGeom.Mesh we must
    # author a `primvars:st` Float2Array. This helper writes a planar XY-projection
    # mapping (works correctly for axis-aligned cuboid faces & the AprilTag plane).
    _ensure_planar_st_primvar(mesh_prim, uv_repeat=uv_repeat)
```

The `_ensure_planar_st_primvar` helper iterates the mesh's `points` + `faceVertexIndices`, projects each vertex onto its dominant face axis, and writes a `Float2Array` primvar named `st` with `interpolation=faceVarying`. For repeating wood: project each vertex by `(x % uv_repeat[0]) / uv_repeat[0]` etc.

**Watch out:** Isaac Sim's RTX renderer respects `UsdPreviewSurface`. If MDL turns out to render better, swap to `UsdShade.Shader` with `info:mdl:sourceAsset = @OmniPBR.mdl@`. Cross that bridge if RTX rendering looks flat.

```python
# scripts/utils/h5_loader.py
import h5py
import numpy as np

class H5Reader:
    """Adapter contract between an H5 file and the kinematic replay loop.
    Concrete schema TBD until a sample new-format H5 is supplied; the
    constructor below reflects the assumed layout (Q8) and is the single
    place to update once the schema lands."""

    DEFAULT_CAMERA = "oakd_front_view"
    ARM_KEY  = "observations/qpos_arm_right"   # (N, 7) [x, y, z, qw, qx, qy, qz]
    HAND_KEY = "observations/qpos_hand_right"  # (N, 17)
    IMAGE_KEY_FMT = "observations/images/{camera}/color"   # (N, H, W, 3) uint8
    DEPTH_KEY_FMT = "observations/images/{camera}/depth"   # optional, (N, H, W) float32 in metres

    def __init__(self, h5_path, camera: str = DEFAULT_CAMERA):
        self._f = h5py.File(h5_path, "r")
        self._camera = camera

    @property
    def n_frames(self) -> int:
        return self._f[self.ARM_KEY].shape[0]

    def load_trajectories(self) -> dict:
        return {
            "arm_xyz_quat": self._f[self.ARM_KEY][()],
            "hand_q":       self._f[self.HAND_KEY][()],
            "n_frames":     self.n_frames,
        }

    def image(self, frame_idx: int) -> np.ndarray:
        return self._f[self.IMAGE_KEY_FMT.format(camera=self._camera)][frame_idx]

    def depth(self, frame_idx: int) -> np.ndarray | None:
        key = self.DEPTH_KEY_FMT.format(camera=self._camera)
        return self._f[key][frame_idx] if key in self._f else None

    def close(self): self._f.close()
    def __enter__(self): return self
    def __exit__(self, *_): self.close()
```

1. Quaternion order in `ARM_KEY` — wxyz vs xyzw. Existing repo has `rotation.detect_quaternion_order` for runtime detection; reuse it.

## 9. Risks & Known Gaps

1. **`UsdPreviewSurface` rendering quality on Isaac Sim 5.1.0.0 RTX.** No precedent in the existing repo. If wood/tag textures look flat or wrong, fall back to MDL `OmniPBR.mdl`. Budget a half-day for this fallback.

2. **`primvars:st` UV authoring on procedurally-built `UsdGeom.Mesh`.** Easy to get wrong. The planar-projection helper described in §6.4 works for axis-aligned cuboid faces and the AprilTag plane, but the cuboid table has six faces with three different normal directions — you must project per-face onto each face's tangent plane, not project all six onto a single plane.

3. **AprilTag detector dependency.** `pupil-apriltags` (recommended) is a small C++/Python wheel; ensure it installs cleanly into conda env `3dv`. Alternative: `dt-apriltags`, `apriltag` (the original lib). Pick one and pin it.

4. **OAK-D Pro AF distortion model.** This camera has noticeable lens distortion. The current `create_camera_prim` builds a **pinhole** USD camera (no distortion). For replay-side rendering this is usually acceptable (the simulated viewport is your reference), but for AprilTag PnP you must undistort the image before detection or pass `dist` into `cv2.solvePnP`. Do the latter — pass factory `dist` through `cv2.solvePnP` so the recovered extrinsic is correct.

5. **H5 schema drift.** Concrete `H5Reader.ARM_KEY` / `HAND_KEY` are placeholders (Q8). Phase 6 must reconfirm them against a real sample. The existing repo's `rotation.detect_quaternion_order` will catch wxyz/xyzw silently; lean on it.

6. **`panda_link0` local translate inside the USD.** `(-0.00761, -0.00027, -0.47602)` is non-trivial — note the `−0.476 m` Z offset, which will easily trip up the mount-pose math if forgotten. The `cfg.robot.panda_link0_local_translate` constant is intentionally exposed so the math is explicit and inspectable.

7. **Articulation parented under procedural Xform.** Confirmed by USD analysis to be valid (the `PhysicsArticulationRootAPI` on `/Root` survives being added under `/World/Robot`). One subtlety: do not put `PhysicsArticulationRootAPI` on a *parent* of `/World/Robot/Root` — that would create a competing articulation root.

8. **Single-source-of-truth USD path.** If you symlink (`assets/orcav1b... → ../../USDs/...`), be aware that `Path.resolve()` and certain USD path resolvers will canonicalise through the symlink. The Isaac Sim USD loader handles this correctly; just don't use `os.path.realpath` mid-pipeline if you're trying to test with multiple USD variants.

9. **Per-version trajectory regression.** Old branch supported `vda`/`depthpro`/`dav3_tablescale` for evaluation. The new branch defaults to a single trajectory file per `(task, object)`. If you later need to A/B different pose estimators, the cleanest extension is `cfg.task.object_trajectories: dict[str, Path]` rather than re-introducing a global `OBJECT_POSE_PATHS` constant. Mention in `docs/kinematic_replay.md`.

10. **`kinematic_replay.html` → `kinematic_replay.md`.** The HTML file is large (50 KB) and likely auto-generated. If your team's docs pipeline expects HTML, regenerate from the new markdown via your existing toolchain rather than committing the HTML directly.
